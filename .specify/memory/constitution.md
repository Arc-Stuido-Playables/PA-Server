# PA-Server Constitution

## Core Principles

### I. Паритет с референсом

Поведение сервера MUST повторять референсный сервер (`http://79.137.204.81`) 1-в-1 по
маршрутам и механике: `GET /list` — список файлов и форма загрузки, `POST /upload` —
загрузка с перезаписью по совпадающему имени, `GET /files/<имя>` — просмотр плеебла во
viewer-обёртке (для `.html`) или отдача файла как есть (для остальных). Любое отклонение
от поведения референса MUST быть явно описано в спецификации с причиной (принятые
отклонения: только `.html`/`.htm` при загрузке — FR-016).

Rationale: команда уже работает по гайду для референсного сервера — ссылки и процесс
апрува не должны меняться.

### II. Простота

Сервер MUST оставаться одним процессом Node.js без базы данных: хранилище — папка на диске,
метаданные — файловая система. Новые зависимости допускаются только если стандартная
библиотека Node не решает задачу приемлемо (сейчас разрешена одна — `busboy` для потокового
multipart). Фронтенд — статические HTML/CSS/JS без сборщика.

Rationale: сервер будет разворачиваться на Timeweb руками студии — меньше движущихся
частей, меньше точек отказа.

### III. Сохранность файлов

Загрузка MUST быть атомарной: файл пишется во временный файл и переименовывается поверх
старого только после успешного завершения. Оборванная загрузка MUST NOT повреждать уже
опубликованный плеебл. Имена файлов MUST сохраняться в UTF-8 (кириллица, пробелы,
скобки), без «кракозябр».

Rationale: ссылку на плеебл уже могли отправить клиенту; перезалив не должен её ломать.

### IV. Безопасность хранилища

Любое имя файла из запроса MUST нормализоваться до базового имени; обход каталогов
(`..`, `/`, `\`, NUL, служебные имена) MUST отклоняться. Сервер MUST NOT исполнять
загруженный контент на своей стороне — плеебл изолируется в `iframe` со `srcdoc`.
Лимит размера загрузки MUST быть настраиваемым.

Rationale: загружать может любой, у кого есть ссылка, как и на референсе.

### V. Проверяемость

Каждое поведение из спецификации MUST покрываться автоматическим тестом на `node:test`,
который поднимает сервер на временной папке и проверяет ответы по HTTP. Тесты MUST
проходить перед каждым коммитом в `main`.

Rationale: паритет с референсом легко сломать незаметно — тесты фиксируют контракт.

## Технические ограничения

- Runtime: Node.js ≥ 20 (LTS), модули ESM.
- Конфигурация только через переменные окружения (`PORT`, `STORAGE_DIR`,
  `MAX_UPLOAD_MB`).
- Развёртывание: самый младший облачный сервер Timeweb Cloud без домена — Node.js +
  systemd через `deploy/install.sh`, доступ по IP на порту 80 (основной путь); `Dockerfile`
  — альтернатива. Каталог хранилища MUST находиться на постоянном диске.
- Дизайн интерфейса MUST следовать стилю Arc Studio (arc-studio.tech): тёмный фон,
  синий primary `hsl(217 98% 58%)`, моноширинные заголовки, Golos Text для текста.

## Процесс разработки

- Работа ведётся по Spec Kit: constitution → specify → plan → tasks → implement.
- Артефакты фичи лежат в `specs/<NNN-имя>/`.
- Коммиты — атомарные, с осмысленными сообщениями; ветка `main` всегда деплоебельна.

## Governance

Конституция имеет приоритет над остальными практиками проекта. Изменения вносятся
правкой этого файла с повышением версии по SemVer (MAJOR — удаление/переопределение
принципа, MINOR — новый принцип или раздел, PATCH — уточнения) и записью в Sync Impact
Report. Каждый план (`plan.md`) MUST содержать проверку соответствия конституции
(Constitution Check).
