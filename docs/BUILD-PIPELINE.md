# Сборка билдов под сетки с сервера — проверка осуществимости (2026-11-16)

Вопрос: можно ли прямо с PA-Server собирать билды под сетки и прогонять автотесты.

## Вывод

**Можно, но собирать надо не на самом сервере, а в GitHub Actions.** Сервер нажимает
«собрать», GitHub собирает и гоняет тесты, готовые файлы прилетают обратно на сервер.

## Что проверено

Клоны всех 22 репозиториев организации (сентябрь 2026) и пробный прогон `pb_playable14_perfect_shot`
на рабочем ПК: `npm run export` — 5 с, 12 сетей (AppLovin, Meta, Google, IronSource, Liftoff,
Mintegral, Moloco, Pangle, TikTok, Unity, Vungle + стенд), отчёт `dist/networks/report.md`;
`npm test` — 1,2 с, 29 тестов.

| Что | Состояние в репозиториях |
|-----|--------------------------|
| Сборка single-file | есть во всех 15 репо с кодом (`npm run build`) |
| Экспорт под сетки | 10 из 15: серия `pb_*` — `npm run export` (8 репо), Jane и Choose your life — `build:networks`, `ds_playable254` — `pack`. Нет: `cm_playable242`, `ds_playable257`, оба `toh_*` |
| Юнит-тесты (vitest / node:test) | 6 репо — работают где угодно |
| Playtest-боты (headless Chrome) | 5 репо серии `pb_*`, но путь к puppeteer зашит как `C:/Users/Aleksandr/Documents/playable-mcp/...`, Chrome — `C:/Program Files/...`. Вне этого ПК не запустятся без правки |
| Единого контракта команд | нет: `export` / `build:networks` / `pack`, выход то `dist/networks`, то `deliver/`, то `build/` |

## Почему не на самом сервере

- Сервер — 1 vCPU / 1 ГБ RAM / 15 ГБ диска. `tsc + vite build` и headless Chrome на 1 ГБ
  упираются в память, а на время сборки тормозит и раздача плееблов клиентам.
- Диск: исходники Choose your life — 4,3 ГБ, Jane — 1,3 ГБ, плюс `node_modules` по 140–215 МБ
  на репозиторий. Все проекты на 15 ГБ не поместятся.
- Репозитории приватные — серверу понадобился бы токен с доступом к коду всей организации.
  Сервер открыт в интернет и работает по HTTP; держать на нём такой токен рискованно.
- `ds_playable254` из git не собирается вовсе: исходные PSD не закоммичены.

## Рекомендуемая схема

```text
[PA-Server: кнопка «Собрать»] --workflow_dispatch--> [GitHub Actions в репо плеебла]
                                                       npm ci → build → export → тесты
[PA-Server: /list, страница билда] <--загрузка по токену-- html/zip по сетям + отчёт тестов
```

1. В каждом репо плеебла — один и тот же workflow и три команды с фиксированными именами:
   `npm run build`, `npm run export` (выход строго в `dist/networks/`), `npm test`.
2. На сервере: токен для загрузки из CI (сейчас вход только по паролю в браузере),
   приём zip под сети (сейчас только `.html`), страница билда: сети, размеры, статус тестов.
3. Токен GitHub с правом только «запустить workflow» — узкий, не даёт читать код.
4. Playtest-боты: заменить зашитые пути на `puppeteer` из `devDependencies` — в Actions
   Chrome уже есть.

Минуты Actions для приватных репозиториев ограничены тарифом организации; сборка
плеебла — около 1–2 минут.

## Связь с конфигом параметров

Параметры, сохранённые на сервере (docs/PLAYABLE-CONFIG.md), живут только в залитом
`.html`. Чтобы билды под сети собирались с ними, «Собрать» должна передавать значения в
workflow, а сборка — подставлять их в блок `pa-config` до экспорта. Это часть той же работы.

## Альтернатива

Сборочный воркер на отдельном сервере (от 2 vCPU / 4 ГБ / 50 ГБ): всё своё, но это второй
сервер, токен к коду на нём и обслуживание Chrome/Node руками.
