# Конфиг плеебла: параметры, которые можно менять на сервере

Сервер ничего не придумывает сам: он читает параметры, которые плеебл объявил в своём
HTML, показывает их в предпросмотре и записывает новые значения обратно в файл.

## 1. Что положить в плеебл

В `index.html` плеебла (в `<head>`, до скрипта игры) — блок с `id="pa-config"`:

```html
<script type="application/json" id="pa-config">
{
  "speed":     { "value": 120, "min": 20, "max": 600, "step": 10, "label": "Скорость персонажа" },
  "jumpEvery": { "value": 2, "min": 0.5, "max": 6, "step": 0.5, "label": "Прыжок каждые, с" },
  "lives": 3
}
</script>
```

Параметр — это ключ верхнего уровня в одном из двух видов:

| Вид | Пример | Что видно в панели |
|-----|--------|--------------------|
| число | `"lives": 3` | поле с числом, подпись = ключ |
| объект с `value` | `"speed": { "value": 120, "min": 20, "max": 600, "step": 10, "label": "…" }` | подпись, поле, ползунок (если есть `min` и `max`) |

`min`, `max`, `step`, `label` необязательны. Сервер не даст сохранить значение вне
`min…max`. Остальные ключи (строки, флаги, вложенные объекты) сервер не показывает и не трогает.

## 2. Как читать в коде плеебла

```js
const raw = JSON.parse(document.getElementById('pa-config')?.textContent || '{}');
/** Значение параметра или запасное, если блока/ключа нет. */
export function cfg(key, fallback) {
  const v = raw[key];
  if (typeof v === 'number') return v;
  if (v && typeof v.value === 'number') return v.value;
  return fallback;
}

const SPEED = cfg('speed', 120);
```

Читать нужно **при старте**, из DOM — не вшивать значения в бандл при сборке, иначе
сервер поменяет блок, а игра этого не увидит. Блок `type="application/json"` Vite и
`vite-plugin-singlefile` не трогают; сети его не исполняют.

## 3. Что происходит на сервере

1. В предпросмотре (`/files/<имя>.html`) у команды появляется кнопка «Параметры».
   Клиенты по ссылке панель не видят (если на сервере задан пароль входа).
2. Меняете значение — плеебл в рамке сразу перезапускается с ним (ничего не сохранено).
3. «Сохранить» — сервер переписывает блок `pa-config` в файле на диске. Ссылка та же,
   все, кто её откроет, получат новое значение; «Скачать» в списке отдаёт уже изменённый файл.
4. «Сбросить» возвращает последние сохранённые значения.

Важно: сервер меняет только залитый `.html`. В репозитории плеебла значения остаются
прежними — при следующей заливке билда с тем же именем параметры станут такими, как в
билде. Понравившиеся значения нужно перенести в исходник.

## API

`POST /config/<имя>` (после входа), тело `{"values": {"speed": 200}}` →
`200 {"params": [...]}` или `400` с текстом ошибки. Менять можно только параметры,
которые плеебл объявил сам.
