# Feature Specification: Сервер для показа плееблов клиентам

**Feature Branch**: `001-playable-hosting`

**Created**: 2026-09-29

**Status**: Ready for planning

**Input**: User description: "Студия плееблов. Свой сервер, куда заливаются плееблы, чтобы
показывать клиентам. Функционал 1-в-1 с референса http://79.137.204.81/list (список, загрузка,
перезалив по тому же имени, страница просмотра плеебла). Дизайн — в стиле arc-studio.tech.
Собрать локально, деплой — на Timeweb."

## Референс (снято с живого сервера 2026-09-29)

| Маршрут | Поведение референса |
|---------|---------------------|
| `GET /list` | Заголовок «Доступные файлы:», список ссылок `/files/<имя>` по всем файлам папки (сортировка по имени), внизу форма `multipart/form-data` → `POST /upload`, поле `file`, кнопка «Загрузить» |
| `POST /upload` | Сохраняет файл под исходным именем; файл с тем же именем перезаписывается |
| `GET /upload` | `405`, текст «Метод не поддерживается» |
| `GET /files/<имя>.html` | Viewer: слева логотип и кнопка «перезапустить», по центру рамка телефона с плееблом во `iframe` (`srcdoc`), справа переключатель светлый/тёмный фон, кнопки пропорций 9:16 / 16:9 / 3:4 / 4:3, кнопка fullscreen; на узком экране — бургер-меню. Заголовок вкладки = имя файла |
| `GET /files/<имя>` (не html) | Отдача файла как есть (например, `.zip` → `application/zip`) |
| несуществующий файл, `/files/`, прочие пути | `404`, текст «404 page not found» |

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Залить плеебл и получить ссылку (Priority: P1)

Разработчик студии открывает страницу списка, выбирает `.html` файл сборки, нажимает
«Загрузить». Файл появляется в списке; клик по нему открывает страницу просмотра, ссылку
из адресной строки он отправляет на апрув.

**Why this priority**: это весь смысл сервера — без загрузки и ссылки ничего не работает.

**Independent Test**: загрузить файл через форму → увидеть его в списке → открыть ссылку →
плеебл запускается.

**Acceptance Scenarios**:

1. **Given** пустое хранилище, **When** пользователь загружает `04_G5_31пак_EH1234i001v001.html`,
   **Then** его возвращает на список, и в списке есть ссылка
   `/files/04_G5_31пак_EH1234i001v001.html` с тем же именем (кириллица читается корректно).
2. **Given** файл загружен, **When** открыта его ссылка, **Then** плеебл запускается внутри
   рамки телефона, заголовок вкладки — имя файла.
3. **Given** в форме не выбран файл, **When** нажата «Загрузить», **Then** сервер отвечает
   понятной ошибкой и ничего не сохраняет.

---

### User Story 2 - Перезалив правок под тем же именем (Priority: P1)

После правок разработчик заливает билд с тем же именем — ссылка у клиента остаётся прежней
и показывает новую версию.

**Why this priority**: гайд студии прямо требует этого сценария; ломать ссылки клиентам нельзя.

**Independent Test**: загрузить файл, загрузить другой контент под тем же именем, открыть
ссылку — виден новый контент, в списке одна запись.

**Acceptance Scenarios**:

1. **Given** файл `X.html` существует, **When** загружен новый `X.html`, **Then** по ссылке
   отдаётся новый контент, в списке ровно одна запись `X.html`.
2. **Given** загрузка нового `X.html` оборвалась посередине, **When** открыта ссылка,
   **Then** отдаётся прежняя целая версия.

---

### User Story 3 - Просмотр плеебла клиентом (Priority: P2)

Клиент открывает ссылку, смотрит плеебл в рамке телефона, переключает пропорции экрана
(9:16, 16:9, 3:4, 4:3), перезапускает плеебл, разворачивает на весь экран, меняет фон
светлый/тёмный. На телефоне элементы управления прячутся в бургер-меню.

**Why this priority**: это то, что видит клиент; но без P1 показывать нечего.

**Independent Test**: открыть любую ссылку плеебла, прокликать все контролы.

**Acceptance Scenarios**:

1. **Given** открыта страница плеебла, **When** нажата «16:9», **Then** рамка меняет
   пропорции на 16:9, кнопка подсвечена как активная.
2. **Given** плеебл в процессе, **When** нажата «перезапустить», **Then** плеебл
   стартует заново без перезагрузки страницы.
3. **Given** страница открыта, **When** нажата «fullscreen», **Then** плеебл занимает
   весь экран.
4. **Given** ширина экрана < 769px, **When** страница открыта, **Then** контролы скрыты
   за бургер-меню и открываются по нажатию.

---

### User Story 4 - Не-HTML файлы (архивы для сетей) (Priority: P3)

Разработчик заливает `.zip` сборку под конкретную сеть; по ссылке файл скачивается как есть.

**Why this priority**: на референсе такие файлы есть, но основной поток — `.html`.

**Independent Test**: загрузить `.zip`, открыть ссылку — скачивается тот же файл
байт-в-байт.

**Acceptance Scenarios**:

1. **Given** загружен `build_google.zip`, **When** открыта `/files/build_google.zip`,
   **Then** отдаётся исходный файл с типом `application/zip`.

---

### Edge Cases

- Имя с кириллицей, пробелами, скобками, `&`, двойным расширением (`.html.html`) —
  сохраняется и отображается как есть.
- Имя с путём (`../x.html`, `a/b.html`, `C:\fakepath\x.html`) — берётся только базовое имя;
  имя, сводящееся к пустому/`.`/`..`, отклоняется с `400`.
- Файл больше лимита — `413`, существующий файл не затронут.
- Запрос несуществующего файла или каталога — `404 page not found`.
- Обращение к `/upload` не методом POST — `405 Метод не поддерживается`.
- Плеебл содержит кавычки/`'`/`&` в коде — отображается без искажений.
- Одновременная загрузка двух файлов с одним именем — побеждает последняя завершённая,
  файл всегда целый.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Система MUST показывать на странице списка все загруженные файлы в порядке
  сортировки по имени, каждый — ссылкой на страницу файла.
- **FR-002**: Страница списка MUST содержать форму загрузки одного файла с кнопкой
  «Загрузить».
- **FR-003**: Система MUST сохранять загруженный файл под исходным именем (UTF-8) и
  перезаписывать файл с тем же именем.
- **FR-004**: После успешной загрузки пользователь MUST возвращаться на страницу списка,
  где новый файл визуально отмечен.
- **FR-005**: Загрузка MUST быть атомарной: до завершения прежняя версия файла доступна
  без изменений, оборванная загрузка не оставляет мусора в списке.
- **FR-006**: Для `.html`/`.htm` файлов страница файла MUST показывать viewer: логотип
  студии, рамку телефона с плееблом, переключатель пропорций 9:16/16:9/3:4/4:3 (по умолчанию
  9:16), кнопки перезапуска и полноэкранного режима, переключатель светлого/тёмного фона,
  бургер-меню на узких экранах; заголовок вкладки — имя файла.
- **FR-007**: Плеебл MUST встраиваться в viewer целиком (содержимое файла), чтобы ссылка
  работала как один адрес без дополнительных запросов к файлу.
- **FR-008**: Для остальных файлов страница файла MUST отдавать файл как есть с корректным
  типом содержимого.
- **FR-009**: Система MUST отвечать `404` с текстом «404 page not found» на неизвестные
  пути и отсутствующие файлы, `405` «Метод не поддерживается» на не-POST к `/upload`.
- **FR-010**: Система MUST отклонять имена файлов, пытающиеся выйти за пределы хранилища.
- **FR-011**: Максимальный размер загрузки MUST настраиваться (по умолчанию 100 МБ).
- **FR-012**: Интерфейс (список и viewer) MUST быть оформлен в стиле Arc Studio.
- **FR-013** *(дополнение к референсу)*: Корень сайта `/` MUST перенаправлять на `/list`.
- **FR-014** *(дополнение к референсу)*: Страница списка MUST иметь поле быстрого поиска
  по имени (фильтрация на клиенте) и показывать размер и дату изменения файла.
- **FR-015** *(дополнение, выключено по умолчанию)*: Если заданы логин и пароль
  администратора, страница списка и загрузка MUST требовать их (HTTP Basic); страницы
  файлов остаются открытыми для клиентов.

### Key Entities

- **Плеебл/файл**: имя (уникальный ключ, UTF-8), содержимое, размер, дата изменения.
  Ссылка на просмотр — `/files/<имя в URL-кодировке>`.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Путь «открыть список → выбрать файл → загрузить → открыть ссылку» занимает
  не более 30 секунд для файла 5 МБ в локальной сети.
- **SC-002**: 100% ссылок, выданных до перезалива, продолжают работать и показывают новую
  версию после перезалива под тем же именем.
- **SC-003**: Имена файлов из референса (кириллица, пробелы, скобки, `&`) отображаются
  без искажений в 100% случаев.
- **SC-004**: Страница списка с 600 файлами открывается и фильтруется поиском без
  заметной задержки (< 1 с).
- **SC-005**: Все контролы viewer'а работают на десктопе и на телефоне шириной 375px.

## Assumptions

- Авторизации на референсе нет — по умолчанию её нет и здесь (FR-015 выключен).
- Удаление файлов не требуется (на референсе его нет); чистка — вручную на сервере.
- Плееблы — самодостаточные single-file HTML (как требуют рекламные сети), поэтому
  встраивание через `srcdoc` достаточно; относительные ресурсы рядом с файлом не
  поддерживаются (как и на референсе).
- Разрешены любые типы файлов, не только `.html` (на референсе лежат `.zip`).
- Хостинг — Timeweb Cloud; хранилище файлов — постоянный диск/том.
