# Feature Specification: Удаление плееблов по паролю

**Feature Branch**: `002-delete-playables`

**Created**: 2026-09-29

**Status**: Ready for planning

**Input**: User description: "Дай возможность удалять плееблы с сервера (через ввод пароля)"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Удалить плеебл из списка (Priority: P1)

Сотрудник студии на странице списка нажимает «удалить» у файла, вводит пароль удаления и
подтверждает. Файл исчезает из списка и перестаёт открываться по ссылке.

**Why this priority**: без этого чистить сервер можно только через консоль VPS.

**Independent Test**: залить файл → удалить с верным паролем → файла нет в списке, ссылка
отдаёт 404.

**Acceptance Scenarios**:

1. **Given** файл в списке, **When** нажато «удалить», введён верный пароль и подтверждено,
   **Then** строка пропадает без перезагрузки страницы, появляется «Удалено», ссылка → 404.
2. **Given** введён неверный пароль, **When** подтверждено, **Then** показано «Неверный
   пароль», файл на месте.
3. **Given** пароль уже был введён верно в этой вкладке, **When** удаляется следующий файл,
   **Then** пароль подставлен, но подтверждение всё равно требуется.

---

### User Story 2 - Защита от подбора (Priority: P1)

Пароль короткий, сервер публичный — перебор должен быть непрактичным.

**Independent Test**: 5 неверных попыток подряд → дальше отказ «слишком много попыток»
даже с верным паролем, пока не истечёт блокировка.

**Acceptance Scenarios**:

1. **Given** 5 неверных попыток с одного адреса за 15 минут, **When** шестая попытка
   (даже с верным паролем), **Then** отказ `429`, файл на месте.
2. **Given** верная попытка, **When** счётчик был > 0, **Then** счётчик сбрасывается.

### Edge Cases

- Пароль удаления не задан в конфигурации → кнопок удаления нет, запрос удаления → `403`.
- Удаление несуществующего файла → `404`.
- Имя с попыткой выхода за пределы хранилища → `400`.
- Не-POST запрос на удаление → `405`.
- Если включена авторизация списка (ADMIN_USER), удаление тоже требует её.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Каждая строка списка MUST иметь кнопку удаления, если удаление включено.
- **FR-002**: Удаление MUST требовать пароль и явное подтверждение с именем файла.
- **FR-003**: Пароль MUST задаваться в конфигурации сервера и MUST NOT храниться в
  репозитории; без пароля удаление выключено.
- **FR-004**: После 5 неверных паролей с одного адреса за 15 минут удаление с этого адреса
  MUST блокироваться на 15 минут.
- **FR-005**: Успешное удаление MUST убирать файл с диска, из списка и по ссылке (404);
  событие пишется в лог сервера с именем файла и адресом.
- **FR-006**: Пароль MAY запоминаться только в пределах вкладки браузера (sessionStorage).

## Success Criteria *(mandatory)*

- **SC-001**: Удаление файла занимает не более 10 секунд и 3 действий.
- **SC-002**: Подбор 4-значного пароля занимает в среднем > 10 суток (≤ 20 попыток в час).
- **SC-003**: Ни один файл не удаляется без верного пароля (покрыто тестами).

## Assumptions

- Пароль общий для команды (один на сервер), пользователей/ролей нет.
- Корзины/восстановления нет — удаление окончательное (бэкапы — по docs/DEPLOY-TIMEWEB.md).
- Адрес клиента берётся из TCP-соединения (прокси перед сервером нет).
